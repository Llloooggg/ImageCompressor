# AGENTS.md — инструкции для агентов в этом репозитории

Проект: **переписывание ImageCompressor с Python на Go** (семейный фото/видео архив
сжимается до целевого размера/формата; идемпотентно, отказоустойчиво, кросс-платформенно).

**Читай `PLAN.md` в корне — это источник истины по архитектуре и решениям.** Если
решение противоречит `PLAN.md`, сначала обнови `PLAN.md`, потом код.

## Контекст цели (не терять)

- Цель — **максимально сжать медиа без видимых потерь и без потери метаданных/времени**,
  идемпотентно (повтор не трогает готовое) и безопасно (крах не портит данные).
- Это **семейный архив людей**: только фото + видео (+ изредка GIF). Иконок/графики нет.
- Формат обязан **открываться вьюерами** (IrfanView/Windows, Fossify Gallery/Android).
  Была травма: WebP сохранили под именем .jpg → вьюеры ломались. Не повторяем.

## Неизменные правила (критично, данные чувствительные)

1. **Входной тип — только по магическим байтам** (`internal/detect`), расширение не доверять.
   Выход — всегда настоящий формат + честное расширение.
2. **Никогда не пережимать уже ужатое.** Если SHA-256 содержимого файла есть в БД как
   «processed» → файл не трогать. Это основа идемпотентности (наследие Python-SQLite).
3. **Никогда не удалять/перетирать оригинал до успеха.** Схема: кодировщик пишет в соседний
   temp → `fsync` → журнал `staged` BEGIN → **атомарный rename** → DB COMMIT (одной транзакцией).
   Все файловые операции — только через `internal/safefs`.
4. **Меньше — или не трогаем.** Если результат не меньше оригинала — откат temp, не заменяем.
5. **Метаданные (EXIF/ICC/XMP) и fs-время — переносить как в оригинале.** Приватность/GPS НЕ трогать.

## Стек и кросс-платформ

- Go, **`CGO_ENABLED=0`** (обязательно — иначе ломается кросс-сборка). Один статический бинарник.
- Модуль: `github.com/Llloooggg/ImageCompressor`.
- Зависимости: `modernc.org/sqlite` (чистый Go!), `github.com/h2non/filetype`, `golang.org/x/sync/errgroup`.
  **Не тянуть cgo-зависимости** (mattn/go-sqlite3, libvips и т.п.) — сломают `GOOS=linux` с Windows.
- Кодеки — **внешние бинарники**, не библиотеки внутри Go: `ffmpeg`/`ffprobe`, `exiftool`, `avifenc`
  (fallback на ffmpeg для AVIF). Искать в PATH / рядом с бинарником (`internal/tools`). Не «изобретать»
  AV1/AVIF на чистом Go.
- Платформенно-зависимое (fsync каталога) — через build tags (`//go:build unix` / `//go:build !unix`).

## Обязательные внешние утилиты (ставит пользователь — см. README.md)

- **ffmpeg/ffprobe** — видео/AV1, AVIF-fallback.
- **exiftool** — **обязателен** для переноса метаданных (EXIF/ICC/XMP); без него они теряются.
- **avifenc** — **настоятельно рекомендуется** для оптимального AVIF фото/анимации (иначе ffmpeg-fallback).
  Искать/предлагать в `tools/` рядом с exe или в PATH; при запуске печатать предупреждение, если чего-то нет.

## Форматы (окончательно)

- Фото → **AVIF** (визуально-lossless). JPEG XL НЕ использовать (плохо открывается вьюерами).
- Видео → **MP4 + AV1**: default `libsvtav1`, `--gpu`→nvenc/amf/qsv, `--max`→libaom; аудио `-c:a copy`;
  `-movflags +faststart`; `-map_metadata 0`.
- Анимация (gif/аним.webp) → **аним. AVIF** (см. открытый вопрос в PLAN.md).

## Сборка / проверки

- `go build -o dist/mediacompressor.exe ./cmd/mediacompressor` (Windows)
- кросс-сборка: `$env:GOOS="linux"; $env:CGO_ENABLED="0"; go build -o dist/mediacompressor ./cmd/mediacompressor`
- обязательно перед коммитом: `go vet ./...` и `go test ./...`
- PowerShell: `CGO_ENABLED=0 ...` НЕ работает как префикс — пиши `$env:CGO_ENABLED="0"; go ...`

## Стиль

- Идиоматичный Go: `context.Context` на всех долгих операциях и внешних процессах;
  параллелим `errgroup.SetLimit(workers)`; ошибки оборачивать `fmt.Errorf("...: %w", err)`;
  `database/sql` + `modernc.org/sqlite`.
- Конфиг/флаги (см. PLAN §6, §10b): `--input --output --migrate --gpu --max --photo-q --photo-lossless
  --video-crf --workers --fix-ext --dry-run --yes`. **Дефолты таковы, что exe без аргументов сжимает
  свою папку рекурсивно** (вход = папка исполняемого файла). Дефолты качества: `--photo-q 85`,
  `--video-crf 24`. Подтверждение перед мутированием (skip `--yes`); пауза в конце в TTY.
- Не переусложнять. Оркестратор, а не реимплементация кодеков.

## Структура (см. PLAN §7 за статусами)

- ГОТОВО (сборка win+linux, vet, тесты зелёные): `internal/detect`, `internal/safefs`,
  `internal/store`, `internal/tools`, `internal/meta`, `internal/media`, `internal/runner`,
  `internal/config`, `cmd/mediacompressor`.
- Старая Python-реализация удалена из дерева (осталась только в git-истории). Её SQLite
  `image_compressor.db` **живёт в архиве пользователя** — это миграционный вход для Go (см. PLAN §3).

## Миграция старой БД (важно)

- Go открывает **тот же** `image_compressor.db`, таблица `processed_images(hash, filename)`.
  `internal/store` бесследно добавляет колонки (`tool/migrated/format/media_kind/...`) через `ALTER`,
  старые строки = `tool='legacy-python'`, и сеется хэшами → не ре-компрессит вывод Python.
- `--migrate` = одноразовое «лего»: приводит legacy-выходы к новому канону ровно раз
  (`WHERE tool='legacy-python' AND migrated=0`), ставит `migrated=1`. Можно выпилить позже.

## Чего НЕ делать

- Не трогать приватность/GPS. Не делать graphics/lossless-ветку. Не пережимать ужатое.
- Не тянуть cgo. Не переписывать кодеки внутри Go. Не переименовывать файлы «вслепую» без детекта.
