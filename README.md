# ImageCompressor

Пакетное сжатие семейного фото/видео архива: **фото/анимация → AVIF**, **видео → MP4 + AV1**,
**визуально без потерь**, с **сохранением метаданных и времени**, **идемпотентно** и
**отказоустойчиво** (падение на середине не портит данные). Один самодостаточный exe — кодеки вшиты внутрь.

Дизайн и решения — в [`PLAN.md`](PLAN.md); правила для агентов — в [`AGENTS.md`](AGENTS.md).

## Внешние утилиты и встраивание в exe

Go сам не кодирует — он вызывает внешние бинарники. **По правилам проекта помощники-кодеки
вшиваются прямо в `.exe`** (как оригинал делал `--add-binary "tools/*.exe:tools"` для cjpeg/cwebp):
реализовано через `go:embed` + распаковку дерева в temp при запуске (аналог `sys._MEIPASS`),
сохраняя структуру — поэтому `exiftool.exe` видит рядом `exiftool_files/` (Perl), а `avifenc.exe` самодостаточен.

Уже **встроено** в `dist/image_compressor.exe` (Windows, ~300 МБ): **`avifenc`** (статический, официальный
релиз AOMediaCodec/libavif), **`exiftool`** (exe + дерево `exiftool_files/`) и **`ffmpeg`** (статическая
сборка gyan.dev full: `libsvtav1`, `libaom-av1`, GPU-AV1). **Один exe полностью автономен: фото, видео и
метаданные работают на любом Windows-ПК без установки чего-либо.** `ffprobe` не нужен и не встраивается —
код его не вызывает.

Самодостаточность обеспечивается на этапе сборки: бинарники кладутся в `internal/assets/tools/windows/`
и **не хранятся в git** (`.gitignore`). Положить и пересобрать:

```powershell
# avifenc (статический exe), exiftool (exe + папка exiftool_files/) и ffmpeg.exe
# (статика, full-сборка) -> положить в internal/assets/tools/windows/, затем:
go generate ./cmd/mediacompressor
go build -trimpath -ldflags "-s -w" -o dist/image_compressor.exe ./cmd/mediacompressor
```

Порядок поиска тулзы: `tools/` у exe → `bin/` у exe → каталог exe → `tools/` cwd → **встроенный (temp)** → `PATH`.

## Сборка (Windows)

```powershell
# 1) сгенерировать Windows-ресурс (иконка + версия) — делает icon.ico -> *.syso
go generate ./cmd/mediacompressor

# 2) собрать exe
go build -o dist/image_compressor.exe ./cmd/mediacompressor
```

Кросс-сборка под Linux:
```powershell
$env:GOOS="linux"; $env:CGO_ENABLED="0"; go build -o dist/mediacompressor ./cmd/mediacompressor
```

## Запуск

По умолчанию (двойной клик по exe — ничего указывать не нужно) утилита сжимает **свою папку и все
подпапки**, спросив подтверждение один раз:

```
image_compressor.exe
```

Полезные флаги (все опциональны — подобраны дефолтами, в основном для дебага):
```
--input <папка>      вход (по умолчанию — папка исполняемого файла)
--output <папка>     результат отдельно (иначе — на месте); output = ПОЛНОЕ зеркало входа
                     (копируются и файлы без изменений, включая не-медиа)
--photo-q N          качество AVIF для фото, 0..100 (по умолчанию 85);
                     если фото не сжимается, инструмент сам понижает ступени -6/-12
--photo-vmaf-min F   порог качества для пониженных ступеней фото (по умолчанию 95 = «отличие не
                     видно глазу»; проверка libvmaf против оригинала; 0 = выключить)
--photo-lossless     AVIF без потерь (пиксель-в-пиксель, тяжелее; лестница при этом не используется)
--video-crf N        базовое качество AV1, 0..50 — МЕНЬШЕ = лучше/тяжелее (по умолчанию 28);
                     если файл не сжимается, инструмент сам поднимает ступени +6/+12
--video-vmaf-min F   порог качества для повышенных ступеней (по умолчанию 95 = «отличие не
                     видно глазу»; проверка libvmaf против оригинала; 0 = выключить)
--video-encoder M    auto|gpu|cpu|nvenc|amf|qsv|libaom (auto = GPU с фолбеком на CPU)
--gpu / --cpu / --max  сокращения для --video-encoder
--workers N          параллельные воркеры (по умолчанию ~половина ядер)
--db <файл>          путь к БД (по умолчанию <input>\image_compressor.db)
--migrate            одноразово привести выходы старой Python-версии к новому канону
--fix-ext            отдельный режим: только переименовать врущие расширения (в обычном
                     проходе они чинятся ВСЕГДА, даже без сжатия)
--dry-run            показать план, ничего не меняя
--yes                без подтверждения (для автоматизации)
-v                   подробный лог
```

### Остановка и продолжение

- **Ctrl+C** — штатная остановка: текущие кодировки прерываются, их temps удаляются, уже
  заменённые файлы записываются в БД до конца; в конце — сводка и сообщение «повторный запуск
  продолжит с того же места». Случайно нажал — просто запусти ту же команду снова.
- **Второй Ctrl+C** — немедленный выход (жёсткий). Данные всё равно в безопасности: журнал
  `staged` + атомарные rename при следующем запуске дозавершают или откатывают прерванное.
- Убийство процесса / выключение питания — тот же механизм `Recover()` + очистка temps при старте.

Миграция со старой (Python) версии: положите рядом старый `image_compressor.db` — Go подхватит его,
не будет заново сжимать уже сжатое Python'ом, а `--migrate` один раз приведёт старые выходы к AVIF/AV1.

## Статус и журнал

- **Живая строка статуса** в консоли: время, обработано N/M (%), счётчики (сжато/готово/не
  уменьшилось/переименовано/ошибки), сэкономленные МБ и МБ/с, ETA (по байтам). При перенаправлении
  в файл/pipe — компактные строки каждые 1000 файлов.
- **Журнал `image_compressor.log`** рядом с БД (обычный текст, колонки через таб, UTF-8 с BOM): дата,
  действие (сжат / не уменьшился / исправлено расширение / ошибка), чем было → чем стало, байты
  до/после/экономия, тип, формат, достигнутое качество.
- **БД хранит фактическое качество результата** (колонка `achieved`: `q=85`, `crf=34 vmaf=97.2`) —
  всегда видно, на каком качестве файл уже лежит и есть ли смысл дожимать.

## Гарантии

- **Никогда не пережимает уже ужатое** (SHA-256 + БД `image_compressor.db`).
- **Меньше — или не трогаем** (файл не заменяется, если стало больше).
- **Никогда не ухудшает заметно**: повышенные ступени AV1 (видео) и пониженные ступени AVIF
  (фото) проверяются VMAF против оригинала (порог 95 = отличие не видно глазу); не проходит —
  файл остаётся как есть.
- **Не теряет оригинал при падении**: запись во временный файл → fsync → журнал → атомарный rename →
  фиксация в БД; при следующем запуске прерванные операции дозавершаются/откатываются.
- **Честные расширения**: тип определяется по содержимому, а не по имени; враньё в расширении
  чинится всегда, даже если файл не сжимался.
