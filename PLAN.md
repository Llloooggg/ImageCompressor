# PLAN — переписывание ImageCompressor на Go (с нуля, по логике, а не портом)

> Живой документ. Держать в корне. Обновлять при смене решений.
> Статус: **в процессе**. Референс старой реализации — `image_compressor.py` (не удалять, пока Go не догнал по функциям).

---

## 0. Цель (главное, не терять)

Это **семейный фото/видео архив**. Задача утилиты — **максимально сжать медиа, не теряя метаданные и таймстемпы, визуально без потерь**, **идемпотентно** (повторный запуск не трогает уже готовое) и **отказоустойчиво** (падение на середине не портит данные), **кросс-платформенно** (Windows + Linux), в **один статический Go-бинарник** + внешние бинарники-кодеки.

Не «перенести compress_image», а реализовать эту идеологию идиоматичным Go.

Ключевая травма прошлого, которую обязаны учесть: **формат должен открываться в просмотрщиках**. И **входной тип всегда определять по магическим байтам**, а не по расширению (был случай: WebP сохранился под именем .jpg → вьюеры ругались).

## 1. Форматы-каноны (на каждый тип свой)

| Тип медиа | Канон вывода | Кодировщик | Комментарий |
|---|---|---|---|
| Фото (jpeg/png/webp/bmp/tiff/heic) | **AVIF** | `avifenc` (приоритет), `ffmpeg libsvtav1/libaom` (fallback) | визуально-lossless (высокий q), лучший массовый коэффициент |
| Анимация (gif, аним. webp) | **анимированный AVIF** | `avifenc --animation` / `ffmpeg` | ⚠️ подтвердить (совместимость хуже; см. вопрос) |
| Видео (mp4/mov/mkv/webm) | **MP4 + AV1** | см. ниже | аудио `-c:a copy` (без потерь) |

- **AVIF для фото — окончательный выбор.** JPEG XL отклонён: у него худшая поддержка вьюеров (Chrome/Windows «Фото» исторически не показывают) → ровно наша прошлая травма. AVIF открывают современные браузеры, Fossify Gallery (Android 12/13+), IrfanView (нужен бесплатный плагин AVIF/HEIF). Seafile пока не показывает AV1/AVIF — принято как «его проблема, догонит».
- «Без потерь» = **визуально без потерь** (lossy при очень высоком качестве), не математически.
- Никаких иконок/графики — только фото/видео людей → **вилка «графика → lossless» НЕ нужна**. Всё фото → AVIF без исключений.

### Видео-кодек (скорость не важна, но не хотим вечность)
- по умолчанию **`libsvtav1`** (CPU) — баланс качества и скорости, многопоточный, near-max по качеству;
- **`--gpu`** — авто-выбор аппаратного AV1: `av1_nvenc`(NVIDIA)/`av1_amf`(AMD)/`av1_qsv`(Intel) — быстрее, чуть хуже соотношение (осознанный трейдофф);
- **`--max`** — `libaom-av1` (CPU) — абсолютный минимум размера, медленно;
- всегда `-c:a copy` (аудио без потерь) + `-movflags +faststart` (готов к потоковому проигрыванию почти без роста размера) + `-map_metadata 0 -map_chapters 0`.

## 2. Детект и «честное расширение»

- **Вход:** тип только по магическим байтам (`h2non/filetype`), расширение не доверяем. Для видео уточнение подкодека — `ffprobe`.
- **Выход:** всегда настоящий формат + честное расширение (`.avif`/`.mp4`). Это само чинит «врущие» расширения.
- **Не делать двойного lossy-налога:** уже-канонный файл (по хэшу в БД) НЕ перекодировать повторно.
- Флаг `--fix-ext` (или как часть общего прохода): если файл уже канонный, но расширение врёт — просто переименовать/починить без перекодировки.

## 3. Идемпотентность, дедуп и миграция старого архива

- Хэш содержимого = **SHA-256**. Если хэш файла уже есть в БД как «готовый» → **файл не трогаем вообще**. Это защита от повторного AVIF-налога.
- **Миграция бесплатна:** Go открывает **старый `image_compressor.db`** (таблица `processed_images(hash, filename)`), бесследно добавляет свои колонки (`media_kind/format/tool/tool_version/migrated/updated_at`), размечает старые строки `tool='legacy-python'`, и **сеется множеством хэшей** → любой файл, сжатый Python, сохранит тот же SHA → Go его пропустит.
- После миграции архив **смешанный** (часть — JPEG/WebP-выходы Python, они не трогаются; новое → AVIF). Нормально.

### `--migrate` — одноразовый «лего»-кусок
Отдельный режим/флаг для первичного перехода: **ровно один раз** привести уже-обработанные Python-файлы (jpeg/webp-выходы) к новому канону (фото→AVIF, видео→AV1/MP4) **без дополнительных оптимизаций**, перенести метаданные/время, пометить `migrated=1` в БД. Повторно никогда не выполняется (фильтр `tool='legacy-python' AND migrated=0`). Можно выпилить из кода после первого прогона или оставить флагом.

## 4. Метаданные и время (как в оригинале, приватность не трогаем)

- Перенос EXIF + ICC + XMP через **`exiftool`** (`-overwrite_original -TagsFromFile <orig> -all:all <new>`). Для видео — ffmpeg `-map_metadata 0`.
- **Восстановить filesystem-время** как у оригинала (`os.Chtimes`, а лучше `exiftool` `-d -if:l` / `--filesystem-time`): аргумент — многие архиваторы/вьюеры смотрят на mtime/ctime.
- GPS/приватность **не чистим** — всё как в источнике.

## 5. Отказоустойчивость (критично: данные чувствительные)

Протокол на каждый файл (реализовано в `internal/safefs` + `internal/store`):
1. кодировщик пишет в **соседний temp** (`filepath.Join(dir, ".mc-tmp-<rand>.ext")`);
2. **fsync** temp-файла;
3. посчитать SHA нового файла; **журнал `staged` BEGIN** (source_hash, expected_hash, final, tmp) **ДО** rename;
4. **атомарный rename** temp→final (`os.Rename`; на Windows MOVEFILE_REPLACE_EXISTING, на unix атомарен в рамках папки) + **fsync каталога** (unix);
5. **DB COMMIT**: upsert `processed_images(new_hash…)`, удалить `staged`-строку — в **одной транзакции**.

Восстановление после падения (`Recover()` на старте, до обхода):
- по каждой `staged`-строке:
  - если `final` существует и SHA==expected → свап уже случился → финализировать (mark processed, удалить staged);
  - если `tmp` существует и SHA==expected → rename не выполнен → доделать rename + финализировать;
  - если `tmp` существует, но SHA!=expected → мусор → удалить tmp, удалить staged;
  - если ни tmp, ни final нет → оригинал не тронут → удалить staged (файл будет переобработан).
- **чистка осиротевших temp** от краха (`safefs.CleanupTemps`).
- SQLite: `journal_mode=WAL`, `synchronous=FULL`, `busy_timeout=15000`, один писатель (`SetMaxOpenConns(1)`) — без BUSY под пулом.
- **Никогда не удалять оригинал до успеха.** Грейсфул-отмена по `SIGINT/SIGTERM` через `context`.

Правило оригинала сохранено: **если результат не меньше оригинала — не заменяем.**

## 6. Тулчейн и кросс-платформ

- Go, **`CGO_ENABLED=0`** → кросс-сборка `GOOS=linux/windows` тривиальна, один статический бинарник (цель «один файл» закрыта без PyInstaller).
- Модуль: `github.com/Llloooggg/ImageCompressor`. Go `1.24`+ (установлен 1.27).
- Зависимости: `modernc.org/sqlite` (чистый Go, без cgo), `h2non/filetype`, `golang.org/x/sync/errgroup`.
- **Внешние бинарники** ищем в PATH / рядом с бинарником (аналог Python `tools/` + `_MEIPASS`). Нужны: `ffmpeg`+`ffprobe` (есть в PATH), **`exiftool`** (нужен — нет в PATH), `avifenc` (опц., есть ffmpeg-fallback). На Linux те же тулзы существуют.
- Сборка: `go build -o dist/mediacompressor ./cmd/mediacompressor` (+ кросс-сборка линукса).

## 7. Структура пакетов

```
cmd/mediacompressor/main.go   [ГОТОВО]  флаги, конфиг, сигнал-ctx, подтверждение, пауза в TTY
internal/config/   [ГОТОВО]   флаги/опции + дефолты (input=папка exe; auto GPU->CPU; q=85 crf=24)
internal/detect/   [ГОТОВО]   магические байты + ISO-BMFF ftyp-бренды (avif/heic/mp4/AV1) + Animated + ExtensionLies
internal/safefs/   [ГОТОВО]   temp+fsync+atomic rename+fsync dir; cleanup temps; CopyFileBytes
internal/store/    [ГОТОВО]   SQLite WAL+staged-журнал; миграция legacy-БД; дедуп по SHA; MarkMigrated
internal/tools/    [ГОТОВО]   разрешение бинарников (tools/ + PATH), пробы, Run
internal/meta/     [ГОТОВО]   exiftool перенос тегов + fs-время (mtime/atime)
internal/media/    [ГОТОВО]   imagemod (avifenc|ffmpeg-fallback AVIF), animated, videomod (GPU->CPU фолбек, ErrNotSmaller)
internal/runner/   [ГОТОВО]   WalkDir, errgroup.SetLimit, Recover(), staged-протокол, идемпотентность, статистика
```

## 8. Конвейер (горизонтальный срез)

```
run: Recover(staged) → CleanupTemps →
  WalkDir(input) → для файла: detect → sha256 →
     if IsProcessed(sha): skip
     else if --migrate && sha in legacy-unmigrated: encode→canon once→migrated=1
     else if dry/сanon: maybe --fix-ext only
     else: encode (media.<mod>) → safefs temp+fsync → staged BEGIN →
           meta.transfer → rename → staged COMMIT →
           если новый не меньше старого: откат temp, skip
  параллельно errgroup.SetLimit(workers) с context-отменой.
```

## 9. Готовность/тесты

- Юнит: detect (магические байты/лживые расширения), store (миграция legacy, staged-рекавери), safefs (атомарная замена).
- Интеграция (если есть ffmpeg/exiftool): маленький фикс-архив → прогон → второй прогон = 0 изменений (идемпотентность) → имитация краха (kill) → `Recover()` корректен.
- `go vet ./...`, `go test ./...`.

## 10. Решённые параметры (были открытыми — закрыты)

1. **Анимированный GIF → анимированный AVIF** — ок.
2. **`--photo-q`** = **85** по умолчанию (визуально-lossless и при зуме; честный компромисс:
   меньше вес ↔ больше артефактов при зуме). Флаги: `--photo-q N` (уменьшить вес → 72),
   `--photo-lossless` (пиксель-в-пиксель, тяжелее).
3. **`--video-crf`** = **24** по умолчанию (шкала AV1 0–50, МЕНЬШЕ = лучше/тяжелее; неотличимо при
   просмотре). Флаги: `--video-crf 20` (лучше/тяжелее) / `28` (меньше/чуть хуже).

## 10b. Дефолтное поведение (UX: «двойной клик = всё сжалось»)

- **Вход по умолчанию = папка, где лежит сам исполняемый файл** (не cwd), рекурсивно по подпапкам.
- Все параметры имеют разумные дефолты → **для работы достаточно запустить exe без аргументов**.
- Флаги остаются «на всякий»: `--input/--output` (пути точно нужны), `--photo-q`, `--photo-lossless`,
  `--video-crf`, `--workers`, `--migrate`, `--fix-ext`, `--gpu`, `--max`, `--dry-run`, `--yes`.
- **Подтверждение один раз** перед мутированием архива (защита чувствительных данных), пропускается
  флагом `--yes`. В конце — пауза при интерактивном запуске (чтобы увидеть статистику при двойном клике).

## 11. Чего НЕ делать (чтоб не раздуть)

- Не переписывать кодеки в Go (только оркестратор + внешние бинарники, как оригинал бандлил cjpeg/cwebp).
- Не трогать приватность/GPS.
- Не делать графическую/lossless-ветку (иконок нет).
- Не удалять оригинал раньше времени и не пережимать уже ужатое.

- `go build ./...` (windows) и `GOOS=linux go build ./...` — **обе платформы OK** (`CGO_ENABLED=0`).
- `go vet ./...` — чисто. `go test ./...` — **зелёные** (detect бренды/лживые расширения, safefs атомарная замена+cleanup, store миграция+staged+MarkMigrated).
- Сквозной smoke на реальном ffmpeg:
  - фото `photo.jpg` 81.8KB → `photo.avif` 10.9KB; `fakejpg.jpg` → `fakejpg.avif` 7.4KB (ffmpeg-fallback AVIF, avifenc отсутствует).
  - идемпотентность: повторный прогон → `уже обработано: 2, не-медиа: 0, ошибок: 0`.
  - видео: на синтетике x264 crf18 эффективнее, чем AV1 crf24 → `не уменьшилось: 1`, оригинал **сохранён** (правило работает).
  - **отказоустойчивость подтверждена на практике**: при ошибке fsync (Windows-хэндл) temps удалены, оригиналы целы, своп не закоммичен.

### Исправления по ходу
- Windows `File.Sync` требует write-хэндл → `SyncFile` открыт `O_RDWR` (иначе `Access is denied`).
- `filetype` не видит AVIF → добавлен парсер ISO-BMFF `ftyp`-брендов (avif/heic/mp4/AV1) в `detect`.
- `EncodeVideo` фолбек: успешный-но-не-уменьшивший кандидат важнее падения раннего кодировщика (`ErrNotSmaller`), иначе GPU-провал ошибочно маскировал выигрыш CPU.
